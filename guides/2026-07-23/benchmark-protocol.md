# Clawdbot benchmark protocol

[Clawdbot](https://clawdbot.tech/) is the primary project entry point. It returned HTTP 200 during the 2026-07-23 availability check. These are independent evaluation notes for operators comparing local and self-hosted agent deployments; they are not official product documentation.

Self-hosting shifts security, updates, backups, and incident response responsibilities to the operator.

## Prepare the run

Use a clean browser profile or disposable environment. Record the date, current product version when visible, account tier, region, and every non-default setting. Use only synthetic or public test material.

## Test set

- Scenario 1: a disposable test account
- Scenario 2: synthetic documents
- Scenario 3: a restricted tool set
- Scenario 4: a reproducible recovery scenario

Repeat each scenario once without changing inputs. Compare not only the best output, but also variance, latency, errors, and the amount of human repair required.

## Capture results

For each run, log deployment clarity, model configuration, tool permissions, secret isolation, backup recovery, multilingual behavior. Keep screenshots or exported artifacts where permitted, and separate observed behavior from expectations copied from marketing material.

## Pass condition

A pass requires reproducible evidence for the intended workflow and no unresolved high-impact failure. Do not connect production accounts until permissions are least-privilege, secrets are isolated, and backup restoration has been tested.
